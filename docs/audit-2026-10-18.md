## 0. 摘要

插件已度过 **「能算清楚账」到「能长期看清楚账」** 的阶段；当前真实瓶颈**不在视觉**，而在 **「超载单文件 + 缺 e2e 验证 + 用户高频场景功能缺失」**。代码本身纪律极好（0 个 `any`、0 个 `@ts-ignore`、612 测试全绿、双线策略不破），提供了远超同类的精细度（官方/三方分桶、订阅额度、子智能体归并、汇率与分时计价、余额差对账、CSV 注入防护、回环守卫+Trusted Hosts+Origin 三道墙）。继续往上做，最有回报的方向是：

1. **拆巨石**（P0）—— `UsageBilling.tsx` 5320 行 / `aggregate.ts` 2571 行 / `UsageBilling.module.css` 4735 行 单文件，是稳定性的最大单点风险。
2. **补 e2e 与可视回归**（P0）—— 612 测试全在 jsdom/unit，生产前的最后一次兜底全靠 3080 手测，新手变更的回归成本被低估。
3. **拉满用户会用到的「次级核心」**（P1）—— 会话行点击跳转、定时报告、按模型预算、设置页搜索、当前小时比昨日同刻（issue #93 延后项）。
4. **国际化与可访问性补漏**（P1）—— 仅 zh/en、缺 ARIA & 键盘可达性专项、缺色弱友好自查。
5. **体积防线**（P1）—— bundle 288 KB 已过本仓自设 256 KiB 软警告线（差 29 KB），下次大改动前先审计，可拆懒加载字典 / 图标 / 多 Tab 组件。

**不建议做的**：①加新统计图表（已是稀疏无图表库设计，扩图即扩 bundle）；②加装饰性 logo / 品牌色块（用户历史反馈「丑」的根因是有数据空位被装饰填补——历史教训见 v1.5.0 commit `510a9e4`）；③用 AI 助手自动生成记账解释（与「纯 UI surface、不注入系统提示、不注册工具」的产品边界冲突）。

## 7. 借鉴行业实践时的边界（do / don't）

### ✅ 借鉴

- **GitHub Copilot usage 页**：KPI + 计划条 + 近期活动的时间线；本仓 KPI 已有，建议参考其「近 14 天 lineup」的紧凑密度
- **OpenAI 平台 usage**：按日 × 模型堆叠双视角，本仓已有；可借鉴其「last 7 days · last 30 days」开关紧贴本仓 KPI 范围
- **Anthropic Console**：amount alert 按项目/部门，本仓 U-3「按模型预算」可参考其阈值粒度
- **Stripe Billing Portal**：表格密度、列对齐规范、CSV 公式注入防护（与本仓同款思路）
- **Vercel Usage**：hover for breakdown，本仓 V-2 KPI tooltip 同
- **OpenRouter 仪表盘**：每个模型的「rate limit remaining」与「last 24h spend」独立卡

### ❌ 不做

- **加图表库**（Recharts / ECharts / D3）—— 本仓 「dependency-free SVG」 是设计哲学，单图表组件代码量可控；换库即换 bundle
- **加装饰性 logo / 品牌色块** —— v1.5.0 `510a9e4`「remove provider group logo tile」的根因是用户反馈「丑」——数据空位被装饰填补会被判装饰过头
- **AI 自动解释账单** —— 与「纯 UI surface，不注册工具、不注入系统提示」产品边界冲突
- **加会话导航** 的「完整 cross-plugin 解」 —— 需宿主会话选择通道对齐（README 「Known Limitations」已记）；仅做「告诉 DSH 跳哪里」的轻量协同，不替代宿主
- **多币种内部折算存储** —— 长期人民币不变，外币按汇率显示（`pricing.ts` 当前 model），切换币种不重算历史
